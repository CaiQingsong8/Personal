# 清单、日程与提醒事项隔离设计

> 用户于 2026-10-23 确认本设计；当前等待规格审阅，尚未开始修改应用代码。

## 目标

- 桌面清单的普通事项、Mac 日历日程、Mac 提醒事项保持独立数据域，不因导入或同步复制到其他数据域。
- Today 页面只增加“清单 / 提醒事项”两个子页签；顶层“月历 / 统计”页面保留现有布局。
- Mac 日历普通日程可单独显示或隐藏；节假日和节气始终显示。
- Mac 创建的日程可导入 DeskFlow，编辑后按稳定 ID 回写原日程。
- Mac 提醒事项可导入 DeskFlow；“提醒事项”子页中新建或导入的事项可双向同步。
- 保持 macOS 13 Ventura 兼容与现有 Intel / Apple Silicon Universal 2 构建。

## 方案比较

1. **拆分持久化数据域（采用）**：清单任务、日历日程、提醒事项使用独立模型、数组、同步入口和删除队列。同步服务只接受其所属数据域，防止以后误把清单传入日历或提醒事项。
2. **共享模型上添加来源筛选**：修改较少，但导入、删除和同步仍依赖运行时筛选，无法可靠隔离数据与副作用。
3. **为三类数据增加三个顶层页面**：数据边界清楚，但增加导航层级，且与用户要求的两个 Today 子块不符。

## 界面

### Today

- 在现有 Today 内容内部加入两个子页签：“清单”和“提醒事项”。顶层 Today / 月历 / 统计导航不变。
- “清单”保留当前任务新增、编辑、完成、批量删除、专注计时等功能。
- “提醒事项”按所选日期显示独立提醒事项，支持在此页新建、编辑、完成，并提供导入、同步和连接状态。
- 为兼容现有页面，月历中的提醒事项同步面板保留；Today 提醒事项页复用相同的提醒事项服务和所选列表状态。

### 月历

- 保留现有月历网格、图层按钮、日历同步面板和提醒事项同步面板布局。
- “Mac 日历”普通事件显示偏好默认关闭。符合节假日或节气规则的事件不受该开关影响。
- 清单任务只由“任务”图层显示；日历事件只由“Mac 日历”图层显示。提醒事项只由“提醒事项”图层显示。

### 统计

- 保留现有布局和图表。
- “本月完成”统计清单任务与提醒事项的完成数，不计入日历日程。
- 专注记录和图表继续使用现有数据来源。

## 数据与同步边界

### 独立模型和持久化

- `TodoItem` 只表示 DeskFlow 普通清单事项，不携带日历或提醒事项 EventKit 标识。
- 新增独立的 `CalendarSchedule` 和 `ReminderItem` 模型。它们分别保存标题、备注、日期/时长、完成状态（适用时）、来源 ID、上次同步时间及本地更新时间。
- `PersistedData` 分别保存 `tasks`、`calendarSchedules`、`reminderItems`，并保留各自的待删除队列。
- 现有 `FocusRecord`、计时快照、任务 ID 和本地日期语义保持兼容。

### 日历

- 日历导入只新增或更新 `calendarSchedules`；同步回 Mac 日历只遍历 `calendarSchedules`。
- 在 Mac 日历中新建日程，再通过导入进入 DeskFlow。DeskFlow 可修改已导入的日程，并按原日历事件 ID 更新，不通过普通清单事项创建日历事件。
- 使用稳定 DeskFlow 日程 UUID / EventKit 标识匹配。旧版 `deskflow://task/<UUID>` 标记仍可读取；新写入使用独立日程标记。歧义标识继续报告冲突并跳过，不新建副本。
- 日历待删除队列仅由日程域操作；清单删除不排入日历删除队列。

### 提醒事项

- 提醒事项导入只新增或更新 `reminderItems`；同步到 Mac 提醒事项只遍历该集合。
- 普通“清单”页创建的任务永远不进入提醒事项同步集合。提醒事项页创建的条目可以创建到当前选定的 Mac 提醒事项列表。
- 导入、更新、完成状态和删除按提醒事项自身稳定 ID 处理；提醒事项待删除队列与日历和清单任务隔离。
- 无截止日期的 Mac 提醒事项仍按创建日期作为本地截止日期，无创建日期时使用当天日期；不产生跨日事件。用户设置了具体日期/时间时按原值保存。
- 保持 macOS 13 的 `requestAccess(to: .reminder)` 与旧授权状态分支；macOS 14 及以上继续使用完整访问 API。

## 旧数据迁移

- 一次性从旧版共享 `tasks` 记录迁移：没有外部 ID 的记录留在清单；含日历 ID 的记录映射到日程域；含提醒事项 ID 的记录映射到提醒事项域。
- 同时含两类外部 ID 的旧记录在两个独立域中保留各自的现有关联，沿用原 UUID；迁移过程中不向 Mac 新建或删除日历事件/提醒事项。
- 保留现有待删除队列、任务 ID、专注记录、活动计时快照及导入导出兼容性。迁移成功后写入新格式，后续启动不重复迁移。
- 迁移失败时保留旧数据文件，不覆盖或清空数据；记录可读错误并允许下次重试。

## 失败与安全行为

- 授权未开启或列表失效时不执行外部写入；反馈当前授权/列表状态。
- 多个候选对象共享不唯一外部 ID 时报告冲突并跳过，不创建重复项。
- 删除失败时只保留对应域的待重试记录；不清理其他域的数据。
- 同步成功提示的新增、更新、删除和冲突计数只反映本次目标数据域。

## 验收与验证

- 旧 JSON 可迁移，且清单、日程、提醒事项分别落入正确集合；迁移前后总记录与关联 ID 可核对，迁移不触发 EventKit 写入或删除。
- 清单新增、编辑、完成和删除不会影响 Mac 日历及提醒事项。
- 日历导入、修改回写和重复同步只更新日程 ID，不向清单或提醒事项新增项目。
- Mac 提醒事项导入、DeskFlow 提醒事项页新增、更新、完成、删除都只作用于提醒事项域；普通清单任务不会被同步。
- 月历普通日历事件默认隐藏；开关可切换显示；节假日与节气在开关两种状态下均可见。
- 月历和统计视图的布局保持现状；统计完成数只包含清单和提醒事项。
- 在 macOS 13 API 兼容路径以及 macOS 14+ 完整访问路径下完成类型检查；构建 arm64 和 x86_64 Universal 2 版本并运行语义回归测试。
- `git diff --check` 通过。静态与构建验证不替代真实 EventKit/iCloud 账户点击验证。

## 实施顺序

1. 增加独立数据模型、存储字段与可回滚旧数据迁移。
2. 将日历和提醒事项同步/删除队列改为只接受各自的数据域。
3. 增加 Today“清单 / 提醒事项”子页签，并复用现有提醒同步面板和列表状态。
4. 调整月历日程默认可见性、节假日/节气常显判断及统计输入集合。
5. 更新回归测试、构建 Universal 2 应用、检查迁移样例和完整差异。
